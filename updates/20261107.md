### Azure Front Door の TLS 鍵交換ポリシー（ポスト量子対応）が一般提供開始

**要約**: Azure Front Door で、TLS の鍵交換ポリシーを構成できる機能が一般提供（GA）になりました。ハイブリッド型のポスト量子鍵交換にも対応し、将来の暗号技術の変化に備えた設定ができます。公式ページからは上記の概要のみ確認でき、対応する具体的なアルゴリズムや設定手順までは確認できていません。

**影響**: 将来の量子計算機による「今盗聴して後で解読する」型の攻撃に備える選択肢が、CDN／WAF の入口で提供されます。セキュリティ要件の厳しい企業は、ポリシーの適用可否や互換性を検証する材料になります。

**リンク**: [Generally Available: Azure Front Door TLS key exchange policy with post-quantum](https://azure.microsoft.com/updates?id=577668)

### Windows 11 Insider Preview：Beta／Experimental に新ビルド（Windows Hello のサインイン改善など）

**要約**: 11 月 6 日付で Beta（Build 26320.9876）と Experimental（Build 26340.9882）などの新ビルドが公開されました。Experimental チャネルでは Windows Hello のサインイン／ロック解除が改善され、顔・指紋認証の完了を待たずに PIN を入力でき、先に使えた方法で認証できるようになります（再起動直後などは最初に PIN が必要）。また Experimental（Future Platforms）では、機能を含まない週次の合成 LCU が配信され、バックエンドの更新配信テストに使われます。

**影響**: 企業の Windows 運用担当者にとっては、サインイン体験の変更が将来の正式版に入る前に評価できる機会です。なお、機能は Insider 限定のプレビュー段階であり、本番展開の判断材料にとどめる必要があります。

### GitHub Copilot impact dashboard に Chat と VS Code Agents window の利用状況を追加

**要約**: Agent adoption チャートに Copilot Chat と VS Code Agents window が加わり、機能は合計 9 つになりました。従来「Passive users」だったコホートは「Chat-first users」に改称されています。API の `copilot_feature_engagement.totals_by_feature` には `chat` と `vscode_agent` が追加され、28 日間で 2 日以上利用したユーザーがエンゲージ済みと数えられます。採用フェーズの判定や API 上のコホート値（No Cohort）、コホートの人数は変わりません。

**影響**: チャット中心の利用者が「非アクティブ」と誤解されにくくなり、Copilot 導入効果の測定がより実態に近づきます。ただし採用フェーズには影響しないため、KPI 設計時は区別が必要です。

**リンク**: [Copilot impact dashboard adds chat and VS Code agent usage](https://github.blog/changelog/2026-11-06-copilot-impact-dashboard-adds-chat-and-vs-code-agent-usage)

### GitHub Copilot 利用状況メトリクス API に Copilot コードレビューの詳細と「対応率」を追加

**要約**: エンタープライズ／組織のリポジトリ単位レポートに、Copilot コードレビューのコメントがその後どう扱われたかを示すフィールドが追加されました。評価対象コメント数と、対応済み（提案の適用、Copilot への修正依頼、手動編集、後続 PR での対応表明）の件数を比較して対応率を算出できます。重大度・レビュー階層・コメント種別・カスタマイズ（カスタム指示、Skill、MCP サーバーなど）別の内訳や、レビュー後に人から変更要求がなくマージされた PR 数も取得可能です。コメントは PR のマージ時に評価されます。

**影響**: 「提案ボタンが押された回数」だけでは見えなかった実効性を、リポジトリ別に把握できます。カスタム指示や Skill、MCP が指摘の質に寄与しているかの検証にも使え、導入効果の説明材料になります。

**リンク**: [Usage metrics API adds code review details and addressed rate](https://github.blog/changelog/2026-11-05-usage-metrics-api-adds-code-review-details-and-addressed-rate)

### GitHub Copilot 利用状況メトリクス API がテレメトリ欠落とバージョン不足を可視化

**要約**: ユーザーごとに、IDE や Copilot 拡張が利用状況メトリクスの最小バージョンを満たすか（met／unmet／unknown）を示すフィールドが追加されました。日次レポートには、クライアントのテレメトリがないユーザー数と、最小バージョン未満のユーザー数も含まれます。テレメトリがないユーザーもアクティブ数には含まれますが、コード行数や機能・モデル別の内訳が欠けます。原因としては古いエディター／拡張、IDE テレメトリ無効化、プロキシやファイアウォールによる遮断が挙げられています。

**影響**: 管理者は、メトリクスの欠損がある利用者を特定して是正できるため、レポートの精度向上につながります。2 つの数は重複し得るため、合算しない点に注意が必要です。

**リンク**: [Usage metrics API flags telemetry and version gaps](https://github.blog/changelog/2026-11-05-usage-metrics-api-flags-telemetry-and-version-gaps)

**影響**: 開発チームは Skill 配布を MCP サーバーに集約でき、モデル選定をエージェント自身で自動化する道が開けます。ただし Insiders 版のため、安定版での提供時期や仕様は変わる可能性があります。
