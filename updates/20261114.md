### Azure Data Share の提供終了（2029年11月12日）を発表

**要約**: Azure Data Share が 2029年11月12日に提供終了となることが告知された。それまでにデータ共有のワークロードを Microsoft Fabric へ移行するよう案内されている。移行先として Fabric の外部共有機能などが挙げられているが、移行手順の詳細はリンク先ページを確認できなかったため記載しない。

**影響**: 提供終了まで3年あるため緊急性は低いものの、Data Share を使った社外とのデータ共有パイプラインを持つ組織は、Fabric への移行計画と代替機能の検証を早めに始める必要がある。

**リンク**: [Retirement: Azure Data Share will be retired on November 12, 2029](https://azure.microsoft.com/updates?id=578818)

### GitHub Copilot：Gemini 4 Hydrogen が一般提供開始

**要約**: Google の最新 Flash モデル「Gemini 4 Hydrogen」が GitHub Copilot で一般提供となった。高速で効率的なエージェント型コーディング、ツール利用、複数ステップのワークフロー向けで、Gemini 3.8 Flash より指示追従性が向上しているという。Pro / Pro+ / Max / Business / Enterprise で利用でき、VS Code、Visual Studio、Copilot CLI、コーディングエージェント、Copilot アプリ、github.com、モバイル、JetBrains、Xcode、Eclipse などで選択可能。展開は段階的で、課金は使用量ベース課金のもとプロバイダーの定価に基づく。

### GitHub Copilot：12月14日に複数モデルを廃止

**要約**: 2026年12月14日に、Copilot のチャット・インライン編集・エージェントモード・コード補完を含む全体験で Claude Fable 5、Claude Haiku 4.5、Gemini 3.8 Flash、Gemini 4 Argon、Grok 4.6、Kimi K3 が廃止される。推奨代替は Claude Fable 5.2、Claude Haiku 5.5、Gemini 4 Hydrogen、Gemini 4 Carbon、Grok 4.7 で、Kimi K3 は未定。Claude Haiku 4.5 は年額プランの個人契約者には引き続き提供される。

**影響**: 特定モデル名に依存したワークフローや連携は期限までの切り替えが必要。Enterprise / Business では、グローバル既定を無効にしている場合、代替モデルを手動で有効化する必要がある。

**リンク**: [Upcoming deprecation of selected GitHub Copilot models in December](https://github.blog/changelog/2026-11-13-upcoming-deprecation-of-selected-github-copilot-models-in-december)

### GitHub Copilot アプリが GitHub Enterprise Server に対応（一般提供）

**要約**: GitHub Copilot アプリに GHES アカウントを追加し、リモートリポジトリ・Issue・プルリクエストを扱えるようになった。従来はオプトインのプレビューだったが一般提供となった。先に GitHub.com か GHE.com でサインインし、設定の「アカウント」から追加する。Copilot アプリ 1.2.0 以降が対象で、GHES ではクラウドセッションは利用できない。

### GitHub コードスキャン：AI Scan を REST API で管理可能に（パブリックプレビュー）

**要約**: 組織・リポジトリ単位で、AI Scan for repositories のオン／オフを REST API から設定できる。既存の AI Scan エンドポイント（`/orgs/{org}/code-scanning/ai-scan`、`/repos/{owner}/{repo}/code-scanning/ai-scan`）に `repository_scan` 設定が追加された。有効化してもスキャンは自動開始されず、書き込み権限を持つユーザーがオンデマンドで実行し、実行ごとに GitHub Code Security の AI クレジットを消費する。GHES は非対応。

**影響**: スクリプトや IaC で大規模に展開・統制できる。一方でスキャンごとにクレジットを消費するため、運用ルールとコスト管理の設計が必要になる。

**リンク**: [Manage AI Scan for repositories using the REST API](https://github.blog/changelog/2026-11-13-manage-ai-scan-for-repositories-using-the-rest-api)
