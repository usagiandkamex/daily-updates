### Key Vault 参照は本当に得か：Terraform state から秘密値を外す設計判断

**要約**: Azure Container Apps などで API キーやクライアントシークレットを Secret に入れても、その値を Terraform に渡していれば state に残ることがあると指摘する記事です。`sensitive = true` は CLI 上の表示を伏せるだけで、保存場所が減るわけではない点を整理しています。

**影響**: IaC を運用する開発者・インフラ担当は、state ファイルの保管先とアクセス制御、Key Vault 参照の採用可否を設計段階で見直す必要があります。

**リンク**: [Key Vault参照は本当に得か — Terraform stateから秘密値を外す設計判断](https://zenn.dev/kmryst/articles/azure-key-vault-terraform-state-design)

### nginx を OpenResty へ差し替え、Entra ID とアプリ内ユーザーを追跡できるログを実装

**要約**: IaaS 中心の経験を持つ担当者が、PaaS やコンテナ構成の設計・構築で既存 OSS の nginx を OpenResty に差し替え、Entra ID とアプリ内ユーザーを追跡できるログを作った事例の紹介です。

**影響**: Entra ID 認証を使う業務アプリで、監査やトラブルシュートに必要なユーザー単位のログをどう確保するかの実践例として参考になります。

**リンク**: [既存OSSのnginxをOpenRestyへ差し替え、Entra IDとアプリ内ユーザーを追跡できるログを作った話](https://zenn.dev/gritio28tech/articles/7b48f4db2d2bfa)
