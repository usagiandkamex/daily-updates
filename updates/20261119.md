## 1. Azure アップデート情報

### Azure Front Door Premium WAF に AI ボットルールセット（パブリックプレビュー）

**要約**: Azure Front Door Premium の Web Application Firewall (WAF) 向けに、AI クローラーやエージェントによるアクセスを扱う AI ボットルールセットがパブリックプレビューとして提供開始された。

**影響**: 生成 AI 向けクローラーによるアクセスが増える中、Web サイト運営者が WAF 側でボット対策を行う選択肢が増える。プレビューのため、本番適用前に検知内容の検証が必要。

**リンク**: [Public Preview: AI bot ruleset for Azure Front Door Premium WAF](https://azure.microsoft.com/updates?id=581604)

---

### Azure Backup が Azure VM のサブスクリプション間バックアップに対応（一般提供）

**要約**: Azure Backup で、Azure Virtual Machines を、VM とは別のサブスクリプションにある Recovery Services コンテナーで保護できるようになった（一般提供）。

**影響**: サブスクリプションを分けて管理している企業で、バックアップを集約したコンテナーに一元化しやすくなり、運用とガバナンスの設計が柔軟になる。

**リンク**: [Generally Available: Cross-subscription backup for Azure Virtual Machines in Azure Backup](https://azure.microsoft.com/updates?id=581048)

---

### Modernize CLI によるアプリ・データベース近代化（パブリックプレビュー）

**要約**: Modernize CLI は、アプリケーションとデータベースの近代化を一連のエージェント型の流れとして提供するツールで、アプリケーションのアーキテクチャなどを評価するところから始まる。パブリックプレビューとして公開された。

**影響**: レガシー資産の移行・刷新の初期評価を自動化でき、移行計画の工数削減が期待できる。ただしプレビュー段階であり、提供範囲の確認が必要。

**リンク**: [Public Preview: AI-powered application and database modernization with Modernize CLI](https://azure.microsoft.com/updates?id=579943)

---

### Azure Disk Storage の不変スナップショット（パブリックプレビュー）

**要約**: Azure のあらゆるディスクのスナップショットに対して、イミュータビリティ（不変性）ポリシーを適用できるようになった（パブリックプレビュー）。

**影響**: ランサムウェアや誤削除への耐性を高めたいバックアップ設計で有用。保持要件のある業種での活用が見込まれる。

**リンク**: [Public Preview: Immutable snapshots for Azure Disk Storage](https://azure.microsoft.com/updates?id=581503)

---

### Cobalt 200 Arm ベース VM が一般提供

**要約**: 汎用の Dpsv7 / Dplsv7、メモリ最適化の Epsv7、高メモリの Mpsv4、高密度ストレージの Lpsv5 シリーズの各 VM が一般提供となった。

**影響**: Arm ベースの VM の選択肢が用途別に広がり、対応ワークロードではコスト・性能の最適化を検討できる。Arm 対応のビルドやイメージの確認は必要。

**リンク**: [Generally Available: Cobalt 200 Arm-based Dplsv7, Dpsv7, Epsv7, Mpsv4, and Lpsv5-series Virtual Machines](https://azure.microsoft.com/updates?id=581298)

---

### Azure Boost による NVMe ディスクの可観測性ツール

**要約**: 互換性のある Azure VM 内で実行する、オープンソースのコマンドラインツール。Azure Boost を基盤に NVMe ディスクの可観測性を提供する。

**影響**: ストレージ性能のボトルネック調査がしやすくなり、I/O 性能が重要なデータベースなどの運用に役立つ。

### GitHub CLI が Event Streams に対応し PR のイベント待機が可能に

**要約**: gh v2.105.0 で、`gh event listen` に PR の URL と対象イベントを指定すると、サブスクリプションを作成してストリームを開き、各イベントを JSON の 1 行として出力する。既定では最初のイベントで終了し、`--count`・`--follow`・`--timeout` で待機方法を調整できる。レビュー提出、PR の状態・head の変更、マージコンフリクト、チェックスイート完了を待てる。プレビュー提供。

**影響**: ポーリングのループが不要になり、スクリプトや AI エージェントが PR の変化を効率よく待てる。CI やレビュー待ちの自動化が簡素化される。

**リンク**: [Wait for pull request events with GitHub CLI](https://github.blog/changelog/2026-11-18-wait-for-pull-request-events-with-github-cli)
