### Windows 11の右クリックメニュー、「散らかっていて重い」とMicrosoftが問題を認める

**要約**: Microsoftが、Windows 11の右クリックメニューがWindows 10時代より「ごちゃごちゃしていて動作が重い」状態になっていることを認め、改善を約束した。複数メディアが同時報道している。

**影響**: 日常的にUIを触るエンジニアやサポート担当にとっては地味に効く話。シェル拡張やコンテキストメニューをカスタマイズしているツール開発者は、今後のUI変更に追従する必要が出てくる可能性がある。

**リンク**: [Microsoft Vows To Fix Windows 11's 'Cluttered And Sluggish' Right-Click Menu](https://hothardware.com/news/microsoft-vows-to-fix-windows-11s-cluttered-and-sluggish-right-click-menu)

### LLMにVega-Liteを直接書かせない、Microsoftのグラフ言語「Flint」

**要約**: LLMにグラフ生成を頼むと大抵60行規模のVega-Lite JSONが返ってくるが、軸フォーマットや色スケールなど一箇所でも噛み合わないと崩れる。そこでMicrosoftはLLMが扱いやすい専用のグラフ記述言語Flintを開発した。

**影響**: LLM経由でのデータ可視化を業務に組み込んでいる開発者にとって、生成物の安定性・可読性を上げる新しいアプローチとして参考になる。

**リンク**: [LLMにVega-Liteを書かせない、Microsoftのグラフ言語Flint](https://qiita.com/okssusucha/items/db25bf29e8d5ad7538e0)

### ecbeingのエンジニアが3年連続で「Microsoft Top Partner Engineer Award」受賞

**要約**: ECプラットフォームを手がけるecbeing社のエンジニアが、Microsoftのパートナーエンジニア向けアワードを3年連続で受賞したと報じられた。

**リンク**: [ecbeingのエンジニア、3年連続で「Microsoft Top Partner Engineer Award」受賞](https://news.yahoo.co.jp/articles/28949bc1e4e539a66f76beb78a9b8afd1dc59717)

## 2. AI

### 「害悪すぎる」と嫌われる“AI営業電話”、企業の自衛策とは

**要約**: AIによる自動架電の営業電話が増加し、対応する企業側からは「手抜きに感じる」「印象が悪い」という不満が噴出している。記事では受け手側が取れる自衛策を紹介している。

**影響**: 自社サービスにAIコールドコール的な機能を組み込もうとしているエンジニア・プロダクト担当は、ブランドイメージへの悪影響というリスクを踏まえた設計判断が必要になる。

**リンク**: [「害悪すぎる」「バカ迷惑」──嫌われまくる“AI営業電話”、今すぐ取れる自衛策は](https://www.itmedia.co.jp/news/article/2608/19/2000000583/)

### AIエージェントは「群れ」にすると壊れる——検証コストの新しい次元

**要約**: 単体のAIエージェント運用では「生成コスト」ではなく「検証コスト」で難易度を見極めることが重要だったが、複数エージェントを群れとして配備すると、個々の出力を検証しても防げない新しい種類の事故が起きるという知見を紹介している。

**影響**: マルチエージェント構成でシステムを組んでいる開発者にとって、単体エージェントの検証設計だけでは不十分であるという実践的な警鐘になる。

**リンク**: [AIエージェントは「群れ」にすると壊れる ——各出力を検証しても、配備が壊す新しい次元](https://zenn.dev/ryok/articles/agent-swarm-verification)

### BINDの脆弱性報告急増、9.20系列にメンテナンスを一本化

**要約**: DNSサーバーソフトウェアBINDについて、脆弱性報告の急増を受け9.20系列へのメンテナンス一本化と毎月のセキュリティアップデートが発表された、というイベントレポート。「LLMによる終末」というキーワードも話題に上っている。

**影響**: DNSインフラを運用するエンジニアは、今後のBINDのアップデート頻度・EOLスケジュールの変化を踏まえたパッチ運用の見直しが必要になる。

**リンク**: [BINDも「LLMによる終末」をすべきなのか……“脆弱性報告”急増で9.20系列にメンテナンス一本化](https://internet.watch.impress.co.jp/docs/event/2133579.html)

## 3. Azure

### Azure VMware Solution（License-included）が2027年8月30日に終了

**要約**: MicrosoftはAzure公式アップデートで、License-includedタイプのAzure VMware Solutionサービスを2027年8月30日に終了すると発表した。背景にはBroadcomによるVMwareライセンスポリシー変更がある。

**影響**: VMwareワークロードをAzure上で運用している企業・インフラエンジニアは、移行計画やライセンス調達方法の見直しを早めに始める必要がある。

**リンク**: [Retirement: Azure VMware Solution License-included service will be retired August 30, 2027](https://azure.microsoft.com/updates?id=569535)

### CommvaultがAzureリカバリを強化、Cloud Rewindを拡張

**要約**: データ保護ベンダーのCommvaultが、Azure環境向けのリカバリ機能「Cloud Rewind」を拡張したと報じられた。

**影響**: Azure上でDR（災害復旧）体制を構築している運用担当者にとって、サードパーティ製リカバリツールの選択肢が広がる情報となる。

**リンク**: [Commvault expands Azure recovery with Cloud Rewind](https://securitybrief.com.au/story/commvault-expands-azure-recovery-with-cloud-rewind)

### SSEの「done」は出力完了ではなく副作用の確定——ストリーミングAPI設計論

**要約**: リクエスト・レスポンス型APIでは「完了」はレスポンス返却と同義だが、ストリーミングAPIにおける「done」イベントは実は副作用の確定を意味するという設計論を、AIエージェントAPIの本番設計シリーズ第2回として解説している。

**影響**: Azure OpenAI Serviceなどストリーミング型のAI APIを本番運用に組み込む開発者にとって、完了状態の扱いを誤ると副作用の二重実行やデータ不整合につながりうるため、設計時の注意点として参考になる。

**リンク**: [SSE の done は「出力完了」ではなく「副作用の確定」 — ストリーミング API の完了をどう定義するか](https://qiita.com/archiningen/items/0ba138687ed0871c2929)
