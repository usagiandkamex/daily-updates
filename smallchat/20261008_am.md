## 2. AI

### OpenAI が「Decisions API」をパブリックベータで公開

**要約**: アプリ内での「どのモデルを使うか」「どのツールを呼ぶか」「問い合わせの振り分け先」といった判断を高速に行う新 API です。テキストと画像を入力でき、条件に当てはまる確率や選択結果、評価スコアを出力します。約10倍高速に判定できるとされています。

**影響**: ルーティングや分類を軽量に切り出せるため、エージェント設計でのレイテンシとコストの最適化に使えそうです。

**リンク**: [OpenAIが判断専用の「Decisions API」を公開](https://gigazine.net/news/20261007-decisions-api/)

### AI で設計されたオープンソース AI アクセラレータ「openTPU」

**要約**: AI エージェントも活用しながら AI 向けハードウェアを設計するオープンソースプロジェクト「openTPU」が公開されました。Qwen3 や Gemma 4 など複数の言語モデルを FPGA 上で動かす試みです。

**影響**: ハード設計にも AI 支援が入り始めており、FPGA で LLM を試したいエンジニアには参照実装として興味深い存在です。

**リンク**: [AIによって開発されたオープンソースのAIアクセラレータ「openTPU」が登場](https://gigazine.net/news/20261007-opentpu/)

### 最近の LLM は「黙って」考えられる

**要約**: 思考の連鎖（CoT）が「喋りながら考える」ことに相当するのに対し、フィラートークンなどを鍵に、出力せずに内部で考える LLM が出てきていると解説する記事です。

**影響**: 推論の中身が見えにくくなるため、評価や監査、デバッグの方法を見直す必要が出てきます。

**リンク**: [最近のLLMは黙って考えられるようになっている](https://joisino.hatenablog.com/entry/filler)

## 4. クラウド

### Aurora PostgreSQL に DuckDB を統合（AWS）

**要約**: Amazon Aurora PostgreSQL に DuckDB が統合され、Apache Iceberg などで構築したデータレイクのデータを ETL なしで直接読み取り・処理できるようになりました。

**影響**: 運用 DB とデータレイクの橋渡しがシンプルになり、分析用パイプラインの削減が期待できます。

**リンク**: [AWS、DuckDBをAurora PostgreSQLに統合](https://www.publickey1.jp/blog/26/awsduckdbaurora_postgresqletl.html)

### ECS の CPU・メモリを Compute Optimizer で安全に見直す

**要約**: 平均 CPU 使用率が低くても、起動直後や負荷集中時の値が隠れるため、単純にサイズを下げると遅延や再試行が増える可能性があります。Compute Optimizer の条件と検証方法がまとめられています。

**影響**: コスト削減時は平均値だけでなくピークとテールを見て検証する習慣が大切です。

**リンク**: [ECSのCPU・メモリを安全に見直す Compute Optimizerの条件と検証](https://qiita.com/s_horikoshi/items/67423c25ebabacda12e5)

### AgentCore × Cognito の MCP が ChatGPT から繋がらなかった話

**要約**: Cognito と Bedrock AgentCore Gateway でリモート MCP サーバーを構築し、ChatGPT から認証付きで接続しようとするとエラーになった調査のまとめです。

**影響**: MCP の認証連携はクライアントごとに要件が異なるため、事前に対応状況を確認しておくと手戻りを防げます。

**リンク**: [AgentCore × CognitoでMCPを作ったけど ChatGPT から使えなかった](https://qiita.com/ny7760/items/e9751e16289b8c5c7c05)
