## 1. Microsoft

### Windows 11、8GB RAM 構成のパフォーマンスを改善

**要約**: Microsoft は、メモリが限られたマシンで Windows 11 の応答性が約 20% 向上し、マルチタスクが約 40% 速くなったと説明している。AI 需要でメモリ価格が上がり続ける状況への対応という位置づけ。

**影響**: 8GB RAM の端末は社内の旧型 PC や検証用 VM にまだ多い。ライセンスや端末の更新を急がずに済む可能性があるが、実機での効果は自分の環境で確認しておきたい。

**リンク**: [Windows 11 8GB RAM configurations get a performance boost](https://www.reddit.com/r/microsoft/comments/1xmyx5c/windows_11_8gb_ram_configurations_get_a/)

## 2. AI

### ADR を rego で lint する

**要約**: 設計判断を ADR として残し、その多くを Claude Code に書かせているリポジトリで、AI が書く ADR のフォーマットを rego（Open Policy Agent のポリシー言語）で機械的に検査する取り組みの紹介。

**影響**: AI が生成するドキュメントの体裁は揺れやすい。レビューで人が指摘するより、CI でポリシーとして検査する方が運用しやすい。

**リンク**: [ADRをregoでlintする](https://zenn.dev/babarot/articles/regomark-adr-checker)

### サム・アルトマン「バグを全部修正するのはもう無理」

**要約**: AI によって巨大な脆弱性が日々見つかり、修正より先に AI の自動操作で悪用されてしまう事案が出ている、という文脈でアルトマン氏の発言を取り上げた記事。

**影響**: 脆弱性の発見が AI で加速する以上、パッチ適用の速度、依存関係の棚卸し、被害を局所化する設計がこれまで以上に重要になる。

**リンク**: [サム・アルトマン「バグ全部修正するのはもうムリ」](https://www.gizmodo.jp/article/sam-altman-ai-cybersecurity-bug-patching/)

### 常駐型 AI エージェント「Muse」のセキュリティ設計

**要約**: Meta が公開した「How We Built Safety Into Muse」を npaka 氏が解説。Muse は個人情報を記憶し、メール確認、予定管理、買い物、Web 操作を自律的に行う常駐型エージェント。

**影響**: 個人情報と外部操作を持つエージェントでは、権限の分離や操作の確認設計が肝になる。自社でエージェントを作る際の参考になる。

**リンク**: [個人情報を扱う常駐型AIエージェント「Muse」のセキュリティの仕組み｜npaka](https://note.com/npaka/n/ncccb2783a262)

## 3. Azure

### Application Gateway for Containers: JWT 検証（Public Preview）

**要約**: AuthPolicy カスタムリソースにより、JSON Web Token の検証をゲートウェイで一元的に行えるようになった。

**影響**: アプリごとに認証ロジックを持たず、Kubernetes 上でポリシーとして宣言できる。API 保護の実装が減る。

**リンク**: [Public Preview: JWT validation for Application Gateway for Containers](https://azure.microsoft.com/updates?id=576382)

### Application Gateway for Containers: MCP ゲートウェイ（Public Preview）

**要約**: 新しい MCPRoute カスタムリソースにより、Model Context Protocol のルーティングに対応した。

**影響**: MCP サーバーを社内に公開する際の入口を、既存のゲートウェイで統一管理できる可能性がある。AI エージェント基盤を作るプラットフォーム担当者に関係が深い。

**リンク**: [Public Preview: MCP gateway for Application Gateway for Containers](https://azure.microsoft.com/updates?id=576388)

### Application Gateway for Containers: プライベート ingress（Public Preview）

**要約**: 承認された Private Link のプライベートエンドポイント経由でのみ到達できるプライベートフロントエンドに対応した。

**影響**: 公開せずに閉域で提供したい内部向けサービスの構成が取りやすくなる。

**リンク**: [Public Preview: Private ingress for Application Gateway for Containers](https://azure.microsoft.com/updates?id=576393)
