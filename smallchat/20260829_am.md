# 2026/08/29 テクニカル雑談（午前）

## 1. Microsoft

### Windows 11 KB5120998 が公開、35件の変更・修正を含む大型累積更新

**要約**: MicrosoftがWindows 11向け累積更新プログラムKB5120998をリリースした。35項目の変更・不具合修正が含まれる一方、任意更新（プレビュー版）ではカーソル関連の新規バグが報告されており、一部メディアは適用を見送るよう注意喚起している。

**影響**: 開発・検証環境へパッチを適用する前に既知の不具合情報を確認し、業務端末への展開タイミングを慎重に見極める必要がある。特にUIの表示崩れ系バグは自動テストで検知しづらいため、手動確認の追加が望ましい。

**リンク**: [Windows 11 KB5120998 update released with 35 changes and fixes](https://www.bleepingcomputer.com/news/security/windows-11-kb5120998-update-released-with-35-changes-and-fixes/)

### Windows 11 26H2がRelease Previewチャネルへ、今年の機能更新の全貌が明らかに

**要約**: Microsoftは今年のWindows 11機能更新となる26H2をRelease Previewチャネルに投入した。正式リリースに向けた最終検証段階に入り、UIやシステム管理機能の細かな調整が中心となる見込み。

**影響**: エンタープライズ管理者は今のうちにInsiderプログラムやテスト環境で互換性検証を進めておくと、正式リリース後の展開がスムーズになる。既存の管理ポリシーやグループポリシー設定への影響も要チェック。

**リンク**: [Microsoft preps this year's Windows 11 feature tweaks: 26H2 hits Release Preview](https://www.theregister.com/os-platforms/2026/08/28/microsoft-preps-this-years-windows-11-feature-tweaks-26h2-hits-release-preview/5293211)

### Microsoft Foundry上のClaude OpusモデルでStructured Outputsが利用可能に

**要約**: Microsoft FoundryのモデルカタログでデプロイできるClaudeモデルにおいて、Structured Outputs機能が使えるようになった。実践的なNotebookでは、この機能の2つの柱を段階的に検証する構成になっている。

## 2. AI

### Anthropicが物理機器制御の共通規格「MHS」発表、将来的にオープンソース化へ

**要約**: AnthropicはAIエージェントが物理的な機器を安全に操作するための共通仕様「Model Hardware Standard（MHS）」のリサーチプレビューを発表した。まずは科学研究機関や先端製造分野の一部パートナーへ提供し、将来的にオープンソース化する方針。

**影響**: ソフトウェアのAIエージェントがロボットアームや実験装置などハードウェアを直接制御する際の標準インターフェースとなる可能性があり、IoT・製造業向けAI開発者は今後の仕様公開を注視する価値がある。

**リンク**: [Anthropic、AIで物理機器を制御する共通規格「MHS」発表　将来オープンソース化へ](https://www.itmedia.co.jp/news/article/2608/28/2000000897/)

### NVIDIAが次世代メモリ規格「NVHBM」を発表、AI性能向上へ

**要約**: NVIDIAはHBM（広帯域メモリ）を再設計した新規格「NVHBM」を発表した。AIワークロード向けのメモリ帯域・容量効率を改善する狙いがあるとされる。

**影響**: 大規模モデルの学習・推論を行うインフラエンジニアにとって、GPUメモリ帯域の制約がボトルネックになりやすいため、次世代ハードウェアのロードマップとしてコスト・性能設計の参考になる。

**リンク**: [HBMの再設計でAI性能アップへ。NVIDIAが「NVHBM」発表](https://pc.watch.impress.co.jp/docs/news/2136398.html)

### エムスリー、DevinによるAIコーディング運用の試行錯誤を公開

**要約**: エムスリーの技術ブログで、OKFやDiátaxisのフレームワークを活用しながらAIコーディングエージェント「Devin」による問い合わせ対応を運用している事例が紹介されている。AIコーディングの実運用における手探りの工夫が具体的に語られている。

**影響**: AIエージェントを開発チームの実務フローに組み込む際のドキュメント整備や運用ノウハウとして参考になり、同様の課題を抱えるチームにとって導入の指針となる。

**リンク**: [OKFやDiátaxisを活用してDevinによるお問い合わせ対応をしている話](https://www.m3tech.blog/entry/2026/08/27/100000)

## 5. セキュリティ

### ServiceNowにCVSS 10.0の脆弱性3件、認証なしでコード実行・SQL実行のリスク

**要約**: ServiceNowにおいて、CVSSスコア10.0（最高値）の脆弱性が3件確認された。認証なしの攻撃者がコード実行やSQL実行を行える恐れがあるとThe Hacker Newsが報じている。

**影響**: ServiceNowを利用する企業のセキュリティ担当者は至急パッチ適用状況を確認する必要がある。ITSMプラットフォームは全社的な業務基盤であるため、影響範囲の特定と迅速な対応が求められる。

**リンク**: [Three CVSS 10.0 ServiceNow Flaws Could Let Unauthenticated Attackers Execute Code and SQL](https://thehackernews.com/2026/08/three-cvss-100-servicenow-flaws-could.html)

### CISA、「悪用される脆弱性の多くは数十年前に解消されているべきだった」と指摘

**要約**: CISA（米サイバーセキュリティ・インフラセキュリティ庁）は、実際に悪用されている脆弱性の多くが、本来はもっと早期に対処されているべき既知の問題であると指摘した。

**影響**: 基本的なパッチ管理・脆弱性対応プロセスの徹底が依然として最重要のセキュリティ対策であることを再確認させられる内容で、開発チームは新規脆弱性対応だけでなく既知の技術的負債の解消にもリソースを割く必要がある。

**リンク**: [CISA: Most exploited vulnerabilities should have been eradicated decades ago](https://www.theregister.com/security/2026/08/28/cisa-most-exploited-vulnerabilities-should-have-been-eradicated-decades-ago/5293194)

### Visa、オープンソース脆弱性修復ツール「VVAH」をAI機能でアップデート

**要約**: VisaがオープンソースのAIセキュリティツール「VVAH」を更新し、脆弱性修復機能を強化した。AIを活用したサイバーセキュリティツールの改善が進んでいる。

**影響**: 決済業界のような高いセキュリティ要件を持つ組織がAIを活用した脆弱性修復ツールを実際に運用・公開している事例であり、自動修復パイプラインを検討するセキュリティエンジニアの参考になる。

**リンク**: [Visa updates open-source VVAH tool with vulnerability remediation](https://www.developer-tech.com/news/visa-updates-open-source-vvah-tool-vulnerability-remediation/)
