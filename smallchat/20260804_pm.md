## 1. Microsoft

### 「Skill Recorder」でデスクトップ操作からAI自動化を生成

**要約**: Microsoftがデスクトップ操作を記録してAIのスキル・自動化を生成できるオープンソースアプリ「Skill Recorder」を公開した。Windows 11、macOS、Ubuntuに対応するクロスプラットフォーム設計になっている。

**影響**: 手作業の操作記録からRPA的な自動化フローを作れるようになるため、業務自動化のハードルが下がる。OSSかつマルチOS対応なので、社内ツールやワークフロー自動化の実装検討材料になりそう。

**参考リンク**: [デスクトップ操作を記録してAIのスキル・自動化を生成。Microsoft、「Skill Recorder」を公開／Windows 11、macOS、Ubuntuに対応するオープンソースアプリ](https://forest.watch.impress.co.jp/docs/news/2130221.html)

### MicrosoftがWindows 11の「監視疑惑」を否定

**要約**: Windows Latestの報道によると、Windows 11に組み込まれたあるサービスがユーザーのデスクトップを「監視している」との疑念が広がったが、Microsoftはこれを否定し、当該サービスの実際の役割を説明した。

**参考リンク**: [Microsoft denies Windows 11 is spying on desktop PCs, reveals what the service actually does - Windows Latest](https://www.windowslatest.com/2026/08/04/microsoft-denies-windows-11-is-spying-on-desktop-pcs-reveals-what-the-service-actually-does/)

## 3. Azure

### Azure Gen2 VMで「Trusted Launch as Default」がGA

**要約**: Azureの新規Gen2仮想マシン・スケールセットにおいて、「Trusted Launch as Default（TLaD）」が一般提供（GA）となった。TLaDはセキュアブートや仮想化ベースセキュリティなどを自動的に有効化する機能。

**影響**: 新規VM作成時にセキュリティ機能がデフォルトで有効になるため、運用者は改めて設定しなくても一定のセキュリティベースラインを確保できる。既存の自動化・IaCテンプレートが前提としていた設定と齟齬がないか確認が必要。

**参考リンク**: [[Launched] Generally Available: Trusted Launch as Default](https://azure.microsoft.com/updates?id=568600)

### BicepでのPrivate Endpoint構成、初回デプロイ失敗の罠

**要約**: Qiitaの記事では、BicepでPrivate Endpointを含む構成を作成する際、空のリソースグループへの初回デプロイのみ`ResourceNotFound`エラーで失敗し、再実行すると成功するという依存関係・並行デプロイの落とし穴が解説されている。

**影響**: IaCでのネットワークリソース構築において、リソース間の暗黙的な依存関係を見落とすとデプロイの再現性が損なわれる。Bicep/ARMでのPrivate Endpoint設計時にはデプロイ順序や依存関係の明示化がより重要になる。

**参考リンク**: [BicepでStorage BlobのPrivate Endpoint構成を作る：依存関係と並行デプロイの罠](https://qiita.com/Azuro/items/14ef733e7e0521dd229c)

### Azure DNS Zone削除時の「委任解除」忘れによるサブドメインテイクオーバー対策

**要約**: Qiitaの記事では、Azureでカスタムドメインを管理している場合に、サブスクリプション解約やDNS Zone削除時に「委任解除」を忘れると、サブドメインテイクオーバーのリスクが生じることを解説している。

**影響**: DNS委任の後始末を怠るとドメイン乗っ取りの脆弱性につながるため、クラウド運用者はリソース廃止時のチェックリストにDNS委任解除を含めるべきという教訓になる。

**参考リンク**: [Azure DNS Zone 削除時に忘れてはいけない「委任解除」～サブドメインテイクオーバーを防ぐために～](https://qiita.com/tanhiroshi/items/82a1127056bdef4802d8)

## 5. セキュリティ

### N-ableのパッチバイパス脆弱性がRMMサーバーで悪用される

**要約**: Dark Readingの報道によると、攻撃者がN-ableのパッチバイパスの欠陥を悪用し、RMM（リモート監視管理）サーバーを狙った攻撃を行っていることが確認された。

**影響**: RMMツールは多数のエンドポイントを管理する要となるため、これが侵害されるとサプライチェーン的に被害が拡大するリスクがある。RMM製品を利用する組織は該当パッチの適用状況を至急確認する必要がある。

**参考リンク**: [Attackers Exploit N-able Patch Bypass Flaw on RMM Servers - Dark Reading](https://www.darkreading.com/vulnerabilities-threats/attackers-exploit-n-able-patch-bypass-flaw)

### ポスト量子時代のカウントダウン、決済インフラの脆弱性リスク

**要約**: IBMの寄稿記事では、量子コンピュータの実用化が進むにつれ、既存の暗号方式に依存するグローバル決済インフラが将来的に脆弱になるリスクが「ポスト量子カウントダウン」として警鐘を鳴らしている。

**影響**: 決済システムやセキュリティ基盤を扱うエンジニアにとって、耐量子暗号（PQC）への移行計画を早期に検討し始める必要性が高まっている。長期的な暗号アルゴリズムのライフサイクル管理が重要テーマになる。

**参考リンク**: [The post-quantum countdown has begun: The looming vulnerability in global payment infrastructure - IBM](https://www.ibm.com/think/perspectives/post-quantum-countdown)

### 攻撃者のパッチ適用速度が組織の対応を上回るという調査結果

**要約**: Dataminrのレポートによると、攻撃者が脆弱性を悪用する速度が、組織側のパッチ適用速度を上回っているという実態が報告された（SC Mediaによる報道）。

**影響**: 脆弱性公開から悪用までの時間（Time-to-Exploit）が短縮傾向にあることを踏まえ、組織はパッチ適用プロセスの迅速化や、パッチ適用前の緩和策（WAF、セグメンテーション等）の整備を急ぐ必要がある。

**参考リンク**: [Dataminr report: attackers exploit vulnerabilities faster than organizations patch - SC Media](https://www.scworld.com/brief/dataminr-report-attackers-exploit-vulnerabilities-faster-than-organizations-patch)
