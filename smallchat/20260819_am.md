# 2026/08/19 テクニカル雑談（午前）

## 1. Microsoft

### Microsoft Entra ID、パスキーがデフォルト認証に。SMS・音声認証は廃止へ

**要約**: Microsoftは「Microsoft Entra ID」において、フィッシング耐性の高い認証への移行を目的に、パスキーをデフォルトのサインイン方式とすることを発表した。SMSおよび音声による認証は今後廃止の方向で進められる。

**影響**: SMS認証はフィッシングやSIMスワップ攻撃に弱いことが知られており、パスキー標準化は企業のアイデンティティ管理を扱うエンジニアにとって、認証方式の見直しやユーザー移行計画の検討が必要になるポイントになる。

**リンク**: [Microsoft Entra ID、パスキーをデフォルトの認証に　SMS・音声認証は廃止](https://atmarkit.itmedia.co.jp/ait/articles/2608/18/news039.html)

### Windows 11の右クリックメニュー、Microsoftが「改悪」を認めて改善を約束

**要約**: MicrosoftはWindows 11の右クリックメニューがWindows 10より「もっさりして煩雑」になったことを事実上認め、今後改善に取り組む方針を示した。File Explorerの高速化やカスタマイズ可能なコンテキストメニューのテストも進行中とされる。

**影響**: UIの応答速度はエンドユーザーの生産性に直結するため、社内向けWindows運用担当者やヘルプデスクは今後のプレビュービルドでの変更点を注視しておく価値がある。

**リンク**: [Microsoft admits it made Windows 11 worse than Windows 10 for right-click menus, promises to fix "sluggish and cluttered" UX](https://www.windowslatest.com/2026/08/19/microsoft-admits-it-made-windows-11-worse-than-windows-10-for-right-click-menus-promises-to-fix-sluggish-and-cluttered-ux/)

### Windows 11の「Ask Copilot」タスクバー機能が削除、統合Copilotアプリへ移行

**要約**: Windows 11で提供されていた「Ask Copilot」タスクバー機能が、フィードバックを受けて一旦無効化された。Microsoftは複数に分散していたCopilot体験を単一の統合アプリへまとめる方向にシフトしているとみられる。

**影響**: Copilot関連のUI/UXは頻繁に変更されており、Windows向けにCopilot連携機能を開発・検証しているエンジニアは、機能の出し入れが今後も続く前提でリリース計画を立てる必要がある。

**リンク**: [Windows 11 Ask Copilot Taskbar feature removed as Microsoft pivots to unified app](https://www.windowscentral.com/microsoft/windows-11/microsoft-disables-windows-11s-new-ask-copilot-taskbar-feature-to-incorporate-feedback-as-it-pivots-to-unified-copilot-app)

## 2. AI

### Geminiの生成コンテンツ、AI生成を示す透かし表示をON/OFF可能に

**要約**: Googleは「Gemini」で生成した画像・動画・音楽について、AI生成であることを示す可視の透かし表示をユーザーがON/OFFできるようにした。ただし目に見えない電子透かし（SynthIDなど）は常に有効のままとなる。

**影響**: コンテンツの真正性表示のポリシーは今後規制対応にも関わってくるため、生成AIをプロダクトに組み込む開発者は可視/不可視の透かし仕様の違いを理解しておく必要がある。

**リンク**: [「Gemini」で生成した画像、動画、音楽のAI生成を示す透かし表示をON/OFF可能に／見えない電子透かしは常に有効](https://forest.watch.impress.co.jp/docs/news/2133216.html)

### AIエージェントのメモリ機能、「秘書のメモ帳」で会話履歴管理を理解する

**要約**: AIエージェントが過去の会話内容を記憶・参照する「メモリ機能」の仕組みについて、短期記憶・長期記憶の違いや実装アプローチを解説する記事が公開された。ツールによって記憶の持続性が異なる理由にも触れている。

**影響**: マルチターンの対話やタスク遂行を前提としたAIエージェント開発では、メモリ設計がユーザー体験の質を大きく左右するため、実装パターンの把握はエージェント開発者にとって実務的に有用。

**リンク**: [AIエージェントのメモリ機能とは何か——「優秀な秘書のメモ帳」で会話履歴管理を完全理解](https://qiita.com/handson-lab/items/8fa62a9b3bb8df623d9c)

### Claude Codeのサブエージェント「fork」、既定ONのはずが環境変数1つで無効化されていた事例

**要約**: Claude Code 2.1.232でサブエージェントの「fork」機能（親の会話コンテキストをまるごと引き継ぐ機能）が既定で有効化されたが、特定の環境変数設定により実際には動作しないケースが報告された。

**影響**: CLI型AIツールの設定は環境変数やバージョン差分で挙動が変わりやすく、開発者は「デフォルトで有効」という説明を鵜呑みにせず、実際の動作確認を行う重要性が改めて示された。

**リンク**: [Claude Code の fork、既定ONのはずが使えなかった — 環境変数1つで決まっていた](https://qiita.com/jqit_suwa/items/11f46a9fc9cb429ceaf5)

## 3. Azure

### Azure Firewall、IPv6サポートがパブリックプレビューに

**要約**: Azure Firewallおよび Firewall Policyにおいて、IPv6のサポートがパブリックプレビューとして提供開始された。デュアルスタック構成での設定が可能になる。

**影響**: IPv6移行を進める組織にとって、境界防御であるファイアウォールのIPv6対応は必須条件であり、ネットワーク設計担当者はプレビュー機能の検証を早期に着手できる。

**リンク**: [[In preview] Public Preview: Ipv6 support in Azure Firewall](https://azure.microsoft.com/updates?id=569520)

### Azure App Serviceの「Managed Instance」が一般提供開始

**要約**: Webアプリケーションを最小限の変更でAzure App Serviceへ移行するための「Managed Instance」機能が、一般提供（GA）となった。組織のマイグレーション作業を支援する位置づけ。

**影響**: レガシーWebアプリのクラウド移行を検討しているチームにとって、移行コストや作業工数を抑える選択肢が増えたことになり、既存PaaS移行計画の見直し材料となる。

**リンク**: [[Launched] Generally Available: Managed Instance on Azure App Service](https://azure.microsoft.com/updates?id=568952)

### Azure VMware Solutionのライセンス込みサービス、2027年8月に終了予定

**要約**: Broadcomによる昨年のVMwareライセンスポリシー変更（BYOL方式への移行要求）を受け、Azure VMware Solutionのライセンス込みサービスが2027年8月30日に終了することが発表された。

**影響**: Azure上でVMwareワークロードを運用している企業は、長いリードタイムがあるとはいえ、ライセンス調達方式の切り替えや移行計画を早めに検討し始める必要がある。

**リンク**: [Retirement: Azure VMware Solution License-included service will be retired August 30, 2027](https://azure.microsoft.com/updates?id=569535)

## 4. クラウド

### Amazon Bedrock AgentCore paymentsがGA、AIエージェントの「支払い」を安全に組み込む

**要約**: AIエージェントがAPIやMCPサーバーを介して支払いを完結できるようにする「Amazon Bedrock AgentCore payments」が一般提供された。予算超過・認可不備・監査証跡の欠落といった課題への対策も組み込まれている。

**影響**: エージェントに決済権限を持たせる際のガードレール設計は今後のAIエージェント開発における重要テーマであり、実運用を見据えた決済フローの参考実装として注目される。

**リンク**: [Amazon Bedrock AgentCore payments がGAに：AIエージェントの『支払い』を安全に組み込む考え方](https://qiita.com/yama3133/items/0ee82bd49341685c81d0)

### 【図解】AWS VPCの5つの部品と、外部から繋がらない原因を整理

**要約**: EC2インスタンスを起動したのに外部からアクセスできないといった典型的なトラブルを題材に、AWS VPCを構成する5つの部品（サブネット、ルートテーブル、IGWなど）を図解で整理した入門記事。

**影響**: VPC構成のトラブルシューティングは多くのAWS初学者がつまずくポイントであり、体系的な整理はオンボーディングやチーム内ナレッジ共有の資料として活用しやすい。

**リンク**: [【図解】AWS VPCとは。5つの部品と、外から繋がらない原因を全部まとめた](https://qiita.com/daisuke-nagata/items/beae13c9563f9fc6f7fb)

### BGPのSite-to-Site VPNでトラフィックセレクタを0.0.0.0/0にする理由

**要約**: AWSのSite-to-Site VPNをBGPで構成する際、トラフィックセレクタを敢えて0.0.0.0/0に設定することが正しい理由について、ルーティングの仕組みに踏み込んで解説した記事。

**影響**: VPN経路制御の設計ミスは接続不可やセキュリティホールにつながるため、ネットワークエンジニアにとってBGP方式でのVPN設計時の判断材料として役立つ。

**リンク**: [BGPのSite-to-Site VPNでトラフィックセレクタを0.0.0.0/0にするのはなぜ正しいのか](https://qiita.com/kaiton-ton/items/e06c247e53d6dde79173)

## 5. セキュリティ

### AI活用の脆弱性クリアリングハウス構想、懐疑論と課題に直面

**要約**: AIを活用して脆弱性情報を集約・分析する「クリアリングハウス」構想について、実現性への深い懐疑論や、データ品質・信頼性をめぐる大きな課題が指摘されている。

**影響**: 脆弱性管理の自動化・効率化を検討するセキュリティチームにとって、AI活用の期待と限界を見極める上で参考になる議論であり、過度な自動化依存へのリスク認識にもつながる。

**要約**: 機械学習基盤MLflowに存在するSSRF（サーバーサイドリクエストフォージェリ）脆弱性を悪用し、攻撃者がクラウド環境の認証情報やシークレットを窃取する攻撃キャンペーンが確認された。

**影響**: MLOps基盤を運用する組織は、内部メタデータサービスへのアクセス制御やMLflowのパッチ適用状況を早急に確認する必要があり、AI/MLインフラのセキュリティ強化の必要性を示す事例となっている。

**リンク**: [Attackers Exploit MLflow SSRF Flaw to Steal Cloud Credentials and Secrets](https://thehackernews.com/2026/08/attackers-exploit-mlflow-ssrf-flaw-to.html)

### 米CISA、Ray-Project「Ray」の脆弱性を既知の悪用脆弱性カタログに追加

**要約**: 米サイバーセキュリティ・インフラセキュリティ庁（CISA）が、分散処理フレームワーク「Ray」の脆弱性を「既知の悪用済み脆弱性（KEV）」カタログに追加した。実際の悪用が確認されたことを意味する。

**影響**: Rayを用いた分散AI/MLワークロードを運用している組織は、KEVカタログ登録を受けて優先度高くパッチ適用や設定の見直しを行う必要がある。

**リンク**: [U.S. CISA adds a Ray-Project Ray flaw to its Known Exploited Vulnerabilities catalog](https://securityaffairs.com/197419/security/u-s-cisa-adds-a-ray-project-ray-flaw-to-its-known-exploited-vulnerabilities-catalog.html)
