# 2026/11/17 テクニカル雑談（午前）

## 1. Microsoft

### Microsoft 365 大規模障害、原因は7月の修正に潜んでいた不具合

**要約**: Microsoft は 11 月 15 日（現地時間）、12 日に発生した Microsoft 365 の大規模障害について暫定インシデントレポートを公表した。7 月に適用した修正に潜んでいた不具合が、サーバの負荷増加と処理能力の低下によって表面化し、世界規模に連鎖したという。Copilot や AI エージェントにも影響が及んだと報じられている。

**影響**: 「数ヶ月前の変更が、負荷と容量の条件が重なって初めて顕在化する」というパターンは、自社サービスの運用にも通じる教訓。段階的ロールアウト、容量低下時の挙動確認、SaaS 障害時の業務継続手段の整理を見直すきっかけになる。

**リンク**: [「Microsoft 365」大規模障害、7月の修正で混入した不具合が原因　負荷増と容量減が重なり世界に波及](https://www.itmedia.co.jp/news/article/2611/17/2000003245/)

### Microsoft 365 障害、インドは影響を回避

**要約**: Microsoft 365 の大規模障害に関し、インドでは政府機関などで深刻な影響が出なかったと現地メディアが報じた。政府傘下の国立情報センター（NIC）がセキュリティー対応を担い、中央・州政府向けの情報通信基盤を独自に運用していることが背景とされる。

**影響**: 単一ベンダーのクラウドへの依存度が障害の影響範囲を左右することを示す事例。重要業務では代替経路や自前基盤との併用も選択肢になる。

**リンク**: [マイクロソフト障害、インドは影響回避　独自の情報通信基盤を活用 - 日本経済新聞](https://www.nikkei.com/article/DGXZQOGM164BZ0W6A111C2000000/)

### Windows の緊急アップデートでアクティベーション障害を修正
