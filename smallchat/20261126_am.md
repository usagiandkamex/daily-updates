# 2026/11/26 テクニカル雑談（午前）

## 1. Microsoft

### Microsoft が障害対応で「非常事態（Code Red）」を宣言

**要約**: 11 月中旬に発生したメールや業務ソフトの大規模障害を受け、Microsoft が社内で「非常事態」と位置づけて対策に乗り出すと報じられています。AI も活用し、今後は障害から 1 時間以内の復旧を目指すとのことです。

**影響**: Microsoft 365 や Outlook に業務を依存している組織にとって、復旧目標の短縮は朗報です。ただし、単一ベンダー障害への備えとして、代替の連絡手段や障害時の運用手順は自前でも用意しておきたいところです。

**リンク**: [マイクロソフト、障害対応へ「非常事態」宣言　1時間で復旧へ - 日本経済新聞](https://www.nikkei.com/article/DGXZQOGN251A90V21C26A1000000/)

### 海外メディアも「過去最悪の障害」への Code Red を報道

**要約**: 9to5Mac は、Microsoft が「史上最悪級」と形容される障害への対応として Code Red を宣言したと伝えています。TweakTown は、グローバルな Outlook と Microsoft 365 の障害を受けた動きとして報じています。

**リンク**: [Microsoft declares a Code Red in response to worst ever outage - 9to5Mac](https://9to5mac.com/2026/11/25/microsoft-declares-a-code-red-in-response-to-worst-ever-outage/)

## 2. AI

### 「Claude」、スキルとコネクターの管理を「プラグイン」に統合

**要約**: 窓の杜によると、Claude ではスキルとコネクターの管理が「プラグイン」に統合されました。

**影響**: 拡張機能の管理が一本化されることで、チーム内での設定共有や運用がしやすくなる可能性があります。既存のスキルやコネクターを使っている場合は管理画面の変更点を確認しておくと安心です。

**リンク**: [「Claude」、スキルとコネクターの管理を「プラグイン」に統合 - 窓の杜](https://forest.watch.impress.co.jp/docs/news/2159131.html)

### AnthropicとOpenAIの従業員らが未公開モデルの能力に懸念

**要約**: Axios の報道として GIGAZINE が、Anthropic や OpenAI の複数の従業員が、未公開の最先端モデルの能力が高くなりすぎて一般公開は危険ではと懸念していると伝えています。

**影響**: 今後のモデル公開のペースや制限（段階的公開、利用条件の厳格化など）に影響する可能性があります。AI を組み込むプロダクトでは、提供モデルの変更や制約に備えた設計が重要です。

**リンク**: [AnthropicとOpenAIの従業員らが「未公開モデルが強力になりすぎて一般公開するのは危険」と懸念 - GIGAZINE](https://gigazine.net/news/20261125-anthropic-openai-employees-fear-unreleased-ai-models/)

### 無断販売された日本の書籍に絶版本も、AI 学習目的の大量スキャンか

**要約**: 日販グループの子会社が Anthropic に日本の書籍を無断で販売していた問題で、対象に絶版書籍が複数含まれていたことが分かったと読売新聞が報じています。AI 学習のための大量スキャンが行われた可能性があります。

**リンク**: [Azureで実現するMCP統合・認可設計](https://qiita.com/windagecat/items/c3004f58f640bff68cba)

### Azure VM の暗黙パブリック IP 廃止と ExpressRoute 0.0.0.0/0 で何が壊れるか

**要約**: ExpressRoute と Azure Firewall を組み合わせる構成で、VM の暗黙パブリック IP の廃止と 0.0.0.0/0 の経路広告という複数の仕様が重なると、経路設計が破綻しうることを解説した記事です。

**影響**: 既存のネットワーク構成でアウトバウンド通信が暗黙のパブリック IP に依存していないか、見直しておく必要があります。

**リンク**: [Azure VM の暗黙パブリック IP 廃止と ExpressRoute 0.0.0.0/0 で何が壊れるか](https://qiita.com/tsui20/items/5cd2a5ea5e3c5d0d97ce)

### RAGOps Studio がナレッジグラフの操作に対応

**要約**: RAGOps Studio v0.1.6 が、Foundry IQ (Azure AI Search) の Public Preview で追加されたグラフ検索に対応し、グラフを読み、GQL で問い合わせ、検索結果の多様性を比較できるようになったと紹介されています。

**影響**: RAG の検索精度改善にグラフ検索を試したい場合、検証ツールとして使えます。Public Preview の機能である点には注意が必要です。

**リンク**: [RAGOps Studio がナレッジグラフの操作に対応！](https://qiita.com/nohanaga/items/a4bb09c4c4d2baaba814)

## 4. クラウド

### AWS Sign-In のセッション有効期間を最長 90 日まで設定可能に

**要約**: 2026 年 11 月 23 日、AWS Sign-In のサインインセッション有効期間を、IAM ユーザーや IAM ロールごとに最長 90 日まで設定できるようになったと紹介されています。

**影響**: 長期アクセスキーからの脱却を進めやすくなるアップデートです。ただし、長いセッションはセキュリティ要件とのバランスを考えて設定しましょう。

**リンク**: [(アップデート)脱アクセスキーへの第一歩](https://qiita.com/yama3133/items/ecf02e39e90874ef2ce5)

### OpenTelemetry のログは通信断でどうなるのか

**要約**: アプリのログを OpenTelemetry で送る際、送信先との通信が一時的に止まるとログがどの程度失われるかを、Collector なし／ありで Databricks と CloudWatch を使って検証した記事です。

**影響**: 可観測性基盤の信頼性設計において、Collector を挟むべきかの判断材料になります。

**リンク**: [OpenTelemetry のログは通信断でどうなるのか：Collector なし／ありで Databricks と CloudWatch から見てみる](https://qiita.com/surabe/items/308a3e22b59b6a0e4e50)

### S3 でプレフィックスを指定したら別のものまで出てきた？末尾の「/」の違い

**要約**: S3 で「logs」を指定すると「logs-old」まで一覧に出てくる理由を、プレフィックスと末尾の「/」の違いから解説した記事です。

**影響**: S3 にはフォルダの概念がなく、プレフィックスの前方一致で動く点を押さえておくと、CLI での一覧取得や削除対象の指定ミスを防げます。

**リンク**: [S3で「logs」を指定したら「logs-old」まで出てきた？プレフィックスと末尾の「/」の違い](https://qiita.com/reo_infraengineer/items/cf45adfb9b347c388e21)
